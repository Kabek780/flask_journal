# Журнал «Охота и рыбалка»

Веб-приложение на Flask — тематический журнал, в котором зарегистрированные пользователи публикуют статьи об охоте и рыбалке, читают материалы других авторов и пополняют внутренний баланс. Администратор получает доступ к журналу посещаемости и прогнозу трафика.

## Возможности

- Регистрация и вход пользователей (пароли хранятся в виде хешей).
- Создание, редактирование и удаление статей (удалять можно свои статьи, администратор — любые).
- Загрузка изображений к статьям.
- Импорт текста статьи из файлов `.docx` (как при создании, так и при редактировании).
- Внутренний баланс пользователя и платный доступ к статьям.
- Полнотекстовый поиск по заголовкам и содержимому статей.
- Логирование посещений (IP, User-Agent, пользователь, время).
- Панель администратора с таблицей посещений и графиком, включающим прогноз на 7 дней вперёд.

## Принцип работы

### Архитектура

Приложение построено по классической схеме Flask-проекта с разделением ответственности:

- `app.py` — точка входа: конфигурация, маршруты (контроллеры), обработчики запросов.
- `config.py` — настройки приложения (`SECRET_KEY`, подключение к БД).
- `extensions.py` — инициализация расширений (объект `db`).
- `models/` — модели данных (`User`, `Article`, `ArticleView`, `VisitLog`).
- `forms/` — формы WTForms и их валидация.
- `templates/` — HTML-шаблоны Jinja2, наследующие общий `base.html`.
- `static/` — стили и загруженные пользователями файлы (`static/uploads/`).
- `migrations/` — миграции Alembic для эволюции схемы БД.

### Модель данных

- **User** — пользователь: имя, хеш пароля, флаг `is_admin`, баланс.
- **Article** — статья: заголовок, текст, путь к изображению, автор, дата создания.
- **ArticleView** — факт просмотра статьи пользователем (используется для платного доступа).
- **VisitLog** — запись о посещении страницы: пользователь (может быть гостем), IP, User-Agent, время.

Связи: пользователь → статьи (один ко многим), пользователь → просмотры, статья → просмотры.

### Поток запроса

1. Flask принимает HTTP-запрос и сопоставляет его с маршрутом в `app.py`.
2. Декоратор `@login_required` (Flask-Login) проверяет авторизацию там, где она нужна.
3. Формы валидируются через Flask-WTF (включая CSRF-токен).
4. Данные читаются/изменяются через SQLAlchemy и сохраняются в SQLite.
5. Результат передаётся в Jinja2-шаблон, который наследует `base.html` (навигация, поиск, баланс) и рендерит контент страницы.

### Аутентификация

При регистрации пароль хешируется через `generate_password_hash` (PBKDF2-SHA256) и сохраняется в БД. При входе `check_password_hash` сравнивает введённый пароль с хешем. Flask-Login хранит идентификатор пользователя в сессии и предоставляет `current_user`.

### Работа со статьями

Автор заполняет форму, при необходимости прикрепляет изображение и/или файл `.docx`. Изображения сохраняются в `static/uploads/` под безопасным именем (`secure_filename`), а в БД пишется относительный путь. При загрузке Word-файла текст извлекается по абзацам через `python-docx` и подставляется в содержимое статьи — как на сервере при отправке формы, так и асинхронно через эндпоинт `/upload_word` (AJAX-запрос из шаблона).

### Баланс и платный доступ

У каждого пользователя есть внутренний баланс. Кнопка «Купить» начисляет 1000 единиц. Первое открытие статьи списывает 100 единиц и создаёт запись `ArticleView`; повторные просмотры этой же статьи бесплатны. Если средств недостаточно, доступ блокируется с соответствующим сообщением.

### Посещаемость и прогноз

Хук `@app.before_request` логирует каждый запрос (кроме статики) в таблицу `VisitLog`. В панели администратора (`/admin/visits`) посещения группируются по дням и выводятся в таблице и на графике Chart.js. Для прогноза на 7 дней используется линейная регрессия (`numpy.polyfit`): при достаточном объёме данных строится тренд, иначе берётся среднее значение. Отрицательные прогнозы корректируются, чтобы график не уходил ниже нуля.

## Запуск проекта

### 1. Клонирование и виртуальное окружение

```bash
git clone <адрес-репозитория>
cd flask_journal
python -m venv venv
```

Активация окружения:

```bash
# Windows
venv\Scripts\activate

# Linux / macOS
source venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Применение миграций

```bash
flask db upgrade
```

### 4. Запуск

```bash
python app.py
```

Приложение будет доступно по адресу `http://127.0.0.1:5000/`.

## Роли и доступ

- **Гость** — просмотр списка статей, регистрация и вход.
- **Пользователь** — создание/редактирование своих статей, чтение статей (с оплатой первого просмотра), поиск, пополнение баланса.
- **Администратор** — дополнительно удаление любых статей и доступ к панели посещаемости.

Флаг администратора (`is_admin`) в текущей реализации задаётся в базе данных вручную.

## Примечания

- `SECRET_KEY` в `config.py` задан для разработки — в продакшене его следует вынести в переменные окружения.
- Приложение запускается с `debug=True`, что предназначено только для локальной разработки.
- SQLite-база и загруженные файлы не подходят для многопользовательской нагрузки без дополнительной настройки.
